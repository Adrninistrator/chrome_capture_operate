# 背景与目标

有时需要在网页上执行重复的操作——工单查询、提单、流转、导出数据等。使用本工具能够将这类“人工在网页中的操作”**生成为可重复执行的 Python 脚本**，提高处理效率。

可由 AI 或人工在浏览器执行操作并抓包，由 AI 分析并生成脚本。**人工或AI在前端操作过程中页面上的每一步（点击、填写值、提交等）的事件自动留痕，与网络访问抓包数据通过时间确定执行顺序与含义**，AI 可以准确地生成脚本。

即使目标网站没有接口文档也能支持；生成的脚本基于抓包实测数据编写，执行结果准确、执行高效、成本低，只有脚本生成阶段需要使用 AI，脚本执行阶段不再需要 AI。

可用于生成Web应用接口自动化测试脚本，也可用于安全验证，例如用脚本复现网页请求、验证接口在无登录态或篡改参数时的响应，辅助安全测试。

一句话总结：**由人工或AI自主进行网页操作，后台自动记录毫秒级对齐的前端操作与网络访问数据，使AI基于以上数据生成可重复执行的 Python 脚本。无需接口文档，脚本执行阶段也不再需要 AI。**

# 实现的功能与特点

- **抓包**：提供将Chrome浏览器网络数据抓包生成本地文件的功能，分为索引文件与每次访问的HTTP/HTTPS协议数据文件，对LLM分析友好；支持根据请求类型与访问地址进行过滤，排除干扰数据；提供MCP工具，使AI Agent能够控制抓包

- **前端页面操作自动记录**：点击、输入值、勾选、下拉选择、提交、路由变化等与请求时间线毫秒级对齐，AI不需要靠时间戳猜测哪个请求对应哪次操作；页面刷新后持续记录，密码自动掩码，记录的事件类型可配置

- **提供网站Cookie**：通过Chrome插件与Python应用将Chrome网站的Cookie与Authorization开放为本地HTTP接口（日常Chrome经插件推送，用于抓包的Chrome经CDP实时读取），Chrome插件支持控制需要推送Cookie与Authorization的网站范围，支持网站会话保持；Cookie查询请求逐次留痕到独立日志文件（每天滚动，仅记数量与key），便于安全审计；Chrome插件支持通过程序自动安装，便于非技术人员使用

- **执行脚本**：生成的脚本可通过Python应用快速执行、定时自动执行、系统托盘执行、手工执行，或由AI Agent或其他程序执行；也提供MCP工具供AI Agent调用

# 实现机制说明

## Chrome网络数据抓包

Python 应用启动专用于抓包的 Chrome，该 Chrome 中的网络访问被保存为本地文件：索引文件汇总全部记录并标注各接口首次出现的记录，每次访问单独一个明细文件，内容为重建的完整 HTTP/HTTPS 请求与返回数据，对 LLM 分析友好；抓包期间可记录操作注释，与请求时间对齐保存，便于对齐前端操作与请求；支持按请求类型与网址过滤，排除静态资源等干扰数据。开始抓包时开启“记录前端页面操作”后，向页面注入 DOM 事件监听，自动记录前端操作（点击、填写值、勾选、下拉选择、提交、回车提交、SPA 路由变化等）到统一时间线，页面刷新或跳转后持续记录，密码自动掩码，人工操作与 AI 操作均留痕并区分，记录的事件类型可在“参数配置”标签页选择。

## Chrome Cookie、Authorization提供

分为两个来源，均通过本地 HTTP 接口获取，无需人工复制 Cookie：

- 日常 Chrome：插件安装在日常使用的 Chrome 中，按启动 / Cookie 与 Authorization 变更 / 定时三种时机，把推送范围内的 Cookie 与 Authorization 推送到 Python 服务，仅存内存不落盘；推送范围在插件中配置
- 用于抓包的 Chrome：Python 服务经 CDP 实时读取内存中的 Cookie（含 httpOnly 与分区 Cookie），Authorization 在抓包期间观察请求头缓存；仅内存传递，不保存到文件

由 AI 分析并生成脚本时，可用 Cookie 发起实际请求进行验证；抓包文件中的 Cookie、Authorization 均已掩码，可从用于抓包的 Chrome 的接口获取。

## AI生成操作脚本

LLM根据Chrome抓包数据，结合人工提供的操作与重要数据描述，或者AI Agent调用chrome-devtools-mcp获得的前端页面分析，就能够生成准确的Python脚本。

# 典型操作顺序

典型操作顺序分三种情况：AI自主操作生成脚本、人工操作生成脚本、执行

## AI自主操作生成脚本

1. 安装公共依赖与 AI 自主模式的依赖（nodejs、chrome-devtools-mcp）
2. 在需要使用的 AI Agent 中配置 MCP chrome-devtools-attach、chrome-operate
3. 通过 Python 应用页面页头**AI自主操作Chrome**弹窗启动用于抓包的 Chrome，在其中打开并登录需要生成脚本的网站
4. 编辑提示词模板，补充需要 AI 在前端页面执行哪些操作、需要生成的 Python 脚本的具体要求，提交给 AI Agent 执行，等待 AI 分析并生成脚本（开始抓包时开启注入后，AI 的页面操作也自动留痕；结束后 AI 可把本次会话目录重命名为便于理解的名字——时间戳后追加描述并附人工标记后缀，如 2026_09_28_17_05_48_查询工单列表_人工标记，便于在**抓包记录**标签页识别每次抓包的内容）

## 人工操作生成脚本

1. 通过 Python 应用页面启动用于抓包的 Chrome，在其中打开目标网站，抓包并执行需要生成脚本的操作——**你做的每一步操作（点击、填写、提交）与填写的值会自动记录在抓包数据中，页面刷新后也不会漏**
2. 在 Python 应用页面获得生成脚本的提示词，人工补全操作描述与具体要求后，提交给 AI Agent 执行，等待 AI 分析并生成脚本

## 执行

1. 在日常使用的 Chrome 安装插件并配置 Cookie、Authorization 推送规则，登录需要操作的网站
2. 在 Python 应用页面执行生成的 Python 脚本，或配置为定时自动执行

## 生成脚本的不同方式

|方式|前置条件|适合场景|
|---|---|---|
|AI自主分析页面生成脚本|需安装nodejs、chrome-devtools-mcp，并在AI Agent中配置MCP|页面操作内容多但AI能够理解（如筛选条件多），由AI完成以免人工逐项操作|

两种方式产出的脚本效果相同，仅生成过程不同，可按任务灵活选择。

### 脚本生成结果

AI 在配置的保存目录下生成一个子目录，含四个文件：

- **Python脚本**（如 `main.py`）：生成的脚本本体，运行时通过 Python 服务获取登录态后发起请求
- **README.md**：说明脚本的作用与使用方法
- **baseline.md**：记录接口的数据来源契约（参数格式、可选值、分页与边界行为的实测结论），作为后续修改脚本的依据
- **prompt.md**：记录本次使用的完整提示词，便于追溯生成依据

在**快速执行脚本**标签页左侧选择脚本子目录（示例目录与自定义目录下的脚本均可执行），右侧选择 `.py` 文件，点击**执行**；脚本输出实时展示在页面上，超过执行超时时间未完成会提示执行超时，可点击**结束进程**终止。

首次使用建议先执行示例目录的 `health_check` 脚本，验证从安装到执行的整条链路可用。

![快速执行脚本页](pics/快速执行脚本页.png)

### 定时执行

在**定时执行脚本**标签页新增任务：选择一个生成的脚本，配置两种定时方式之一——**在指定时间执行**（每天 / 每周 / 每月 + 多个具体时间）或**每隔一段时间执行**（从指定时间开始，可配置允许执行的时间段）。

任务支持暂停 / 恢复 / 编辑 / 删除；每次执行生成独立日志，可在该页查看执行日志。

![定时执行脚本页](pics/定时执行脚本页.png)

### 系统托盘执行

![快捷执行脚本-添加到托盘菜单](pics/快捷执行脚本-添加到托盘菜单.png)

之后右键系统托盘图标 → 快速执行脚本 → 点击对应脚本，独立窗口实时展示脚本输出，执行完毕窗口保留显示退出码。

## Chrome插件的其他功能

### 会话保持

长时间不访问目标网站时登录态会过期，定时执行的脚本可能返回未登录。插件定时刷新 Chrome 中已打开的对应页面，主动保持登录会话：在插件**会话保持**标签页配置，每项为域名或IP + 刷新间隔分钟。

![插件会话保持](pics/chrome_extension_会话保持.png)

注意：刷新会使页面上未保存的输入丢失；会话保持依赖对应页面保持在 Chrome 中打开。

### 收藏并打开页面

浏览器中需要长期打开大量网页时，把当前打开的页面收藏为一条记录，之后一键批量打开——浏览器或系统重启后快速恢复整组页面。在插件**收藏并打开页面**标签页操作。

![插件收藏并打开页面](pics/chrome_extension_收藏并打开页面.png)

可导出或导入相关信息

### 配置导入导出

将插件全部配置导出为 `.json` 文件，或从 `.json` 导入，便于在新机器复制配置。在插件**参数配置**标签页操作。

## Chrome进程多开

同一网站需要登录多个账号时，为每个账号创建独立的 Chrome 实例分别登录，各实例数据互不干扰，脚本可按实例编号获取对应账号的登录态。在**Chrome进程多开**标签页点击**新增**，输入名称与本地数据存储目录；每个实例都要安装 Chrome 插件并填写实例编号。

![Chrome进程多开页](pics/Chrome进程多开页.png)

## Cookie 接收与查询记录

插件推送的 Cookie 是否到达 Python 服务、生成的脚本与 AI 的 Cookie 查询情况，均可在 Web 页面**Chrome Cookie接收与查询记录**标签页查看，页面提供两种展示：

- **接收记录**：内存中最近 50 次插件推送（时间、实例编号、原因、地址、数量、成功/失败）
- **查询记录**：当天最新 50 条 Cookie 查询留痕（时间、来源、查询地址、范围、数量、Authorization 有无、成功/失败），从日志文件读取、服务重启不丢

页面下方同时展示日志查看说明（含日志目录完整路径）：更早的完整记录见日志目录——查询记录见 cookie_query.log（每行一条 JSON、每天滚动），插件推送接收记录见按天生成的 yyyy-MM-dd.log 主日志；日志仅记数量与 key，不记录任何 Cookie/Authorization 值。

## 常见问题

|现象|排查|
|---|---|
|页面打不开 / 脚本获取 Cookie 报“服务不可达”|服务未启动——运行 start.bat 或检查系统托盘图标|
|插件未推送 Cookie|检查推送范围是否已从“全部禁止”修改为“全部允许”或按指定范围推送|
|脚本执行返回未登录或 401|推送范围 allow 清单需带 `*.` 通配符；登录态与插件须在同一个 Chrome 中；仍 401 多为会话过期——配置插件会话保持|
|抓不到部分请求|核对抓包配置的过滤开关与网址选择；仅记录 http/https 流量|
|开始抓包提示需先启动 Chrome|先点**启动用于抓包的Chrome**；已启动但检测不到时点**检测Chrome进程**刷新|
|用于抓包的Chrome窗口被其他窗口挡住|点**置顶用于抓包的Chrome进程**按钮调到最前|
|生成提示词时提示需配置脚本保存目录|在**快速执行脚本**标签页的**配置生成的脚本保存目录**填写并保存|
|脚本执行超时|执行超时时间可在**参数配置**标签页调整；或检查脚本是否在等待交互输入|
|定时任务到点未执行|确认任务未被暂停、Python 服务当时正在运行；服务重启后任务自动恢复，期间错过的调度只补执行最近一次|
|抓包记录中没有页面操作注释|确认抓包配置中“记录前端页面操作”已勾选（默认开启）；确认操作发生在用于抓包的 Chrome 中（日常 Chrome 的操作不会记录）|
|操作记录中没有滚动/按下/聚焦事件|默认不记录这三类（与点击重复或纯噪音）；需要时在“参数配置”标签页的“前端操作记录事件类型”中勾选|
|页面操作注释显示“（合成）”|该操作由程序（AI/脚本）触发而非人工点击，标注用于区分操作来源，不影响分析|

通过模拟点击安装 Chrome 插件失败：需日常 Chrome 已运行且界面语言为中文；通过注册表安装需人工点击 UAC 确认框。

# 安全性

本工具处理 Cookie、Authorization 等登录态敏感数据，安全性设计如下。

## Cookie 推送范围

- 插件安装后默认为“全部禁止”——不向 Python 服务推送任何 Cookie 与 Authorization，须人工在插件**参数配置**标签页显式改为“全部允许”或“按指定范围推送”；范围外的网站数据不会离开浏览器
- 推送到 Python 服务的 Cookie 仅存内存、不写入文件，服务重启即清空

## 接口访问范围

- Python 服务的全部接口（Web 页面、Cookie 查询、AI Agent 调用的 MCP 服务）仅监听本机地址（127.0.0.1），局域网内其他电脑无法访问
- 接口不设访问令牌，安全边界即本机——本机登录用户下的程序均可调用
- 网页可修改的插件配置限定为推送范围等白名单字段，推送目标地址不开放网页修改——本机上的任意网页无法把 Cookie 重定向到其他地址

## Cookie 查询留痕

- 所有 Cookie 查询（生成的脚本、AI Agent 等发起的调用）逐次留痕到独立日志文件 `chrome_capture_operate_python/log/cookie_query.log`（每行一条 JSON 结构化记录，每天滚动、不自动删除）；只记录时间、来源、查询地址、返回数量与 key，不记录任何 Cookie/Authorization 值
- 日常查看：Web 页面**Chrome Cookie接收与查询记录**标签页供快速查看——查询记录展示当天最新 50 条（从日志文件读取，服务重启不丢），插件推送接收记录展示内存中最近 50 次；更早的记录在日志文件中完整保存——查询见 cookie_query.log，插件推送接收见按天生成的 `log/yyyy-MM-dd.log`

## 抓包与日志脱敏

- 抓包明细文件中的 Cookie、Authorization 值均掩码为 `***`（key 保留），抓包数据可安全交给 AI 分析；自动记录前端操作时，密码输入框的值自动掩码
- 程序日志同样只记 Cookie 的数量与 key；需要真实登录态验证时经接口在内存中读取，不写入文件

## 数据不出本机

抓包文件、Cookie、日志全部保存在本机，工具自身不向任何外部服务器发送数据；生成的脚本只在本机与目标网站之间通信。
