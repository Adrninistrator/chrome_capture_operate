# QQ 邮箱发票 PDF 附件批量下载（搜索版）

## 脚本作用

登录 QQ 邮箱网页版（`wx.mail.qq.com`，Cookie 由 chrome_capture_operate 服务提供），模拟人工“搜索邮件”的操作并批量下载发票 PDF：

1. **搜索**：调用 `POST /list/search`，条件与人工网页操作一致——关键字「发票」（匹配标题/正文/附件，即“关键字位置=不限”）、所在文件夹=收件箱（`dirid=1`）、每页 50 封，从 `page_now=0` 开始翻页；
2. 搜索结果按时间**从新到旧**逐封处理，对**标题包含“发票”或“报销”且有 PDF 附件**的邮件：
   - 未读：`readmail` 打开（置已读，与人工打开邮件行为一致）后下载 PDF 附件：
     - PDF 附件**只有 1 个**：直接下载（不看文件名，覆盖 `12345678901234567890.pdf` 发票号命名、`【飞猪】…报销凭证.pdf` 等情况）；
     - PDF 附件**有多个**：仅下载文件名包含“发票”或“报销”的 PDF；文件名包含“**行程**”的跳过（如网约车“行程报销单.pdf”）；
   - 已读：说明更早的邮件均已处理过，记录后**立即结束**；
3. **翻页**：若当前页未遇到“满足结束条件的已读邮件”，继续取下一页（上限 20 页；抓包时搜索结果共 885 条 ≈ 18 页）；
4. 记录但不下载（用于发现其他形式的发票邮件）：
   - 有 PDF 附件但标题不含关键字的邮件（第二类）；
   - 标题含关键字但无 PDF 附件的邮件（第三类，如“云票”正文仅链接的发票通知）：
     提取正文中**所有非 QQ 邮箱域名的链接**（`<a href>`，排除 `qq.com` 及其子域、`mailto:`），
     以可点击形式列在汇总中，供人工打开后下载发票；
5. 在下载目录生成《发票附件下载汇总.html》，包含以上三类邮件明细及各 PDF 是否下载；
   每类均显示**邮件接收时间**（`totime`，精确到秒）、**邮件标题**、**PDF 附件文件名**；
   **需人工关注的信息重点显示**：第二类（有 PDF 但标题不含关键字，可能漏掉的发票邮件）、
   第三类（标题含关键字但无 PDF，其他形式的发票邮件）以红色警示框突出，
   下载失败标红、已读停止点标橙。

## 保存位置

- PDF 保存到**桌面**下以当前时间（精确到毫秒）命名的子目录，如 `桌面\20260831_095500_123\`；
- 同名文件自动在文件名后追加序号（如 `发票(1).pdf`）；
- 汇总文件 `发票附件下载汇总.html` 生成于同一子目录（浏览器直接打开查看）；
- 桌面路径通过注册表解析，兼容 OneDrive 桌面重定向。

## 使用方法

1. 启动 chrome_capture_operate（Cookie 服务，默认 `http://127.0.0.1:33445`），并确保浏览器插件已推送 `wx.mail.qq.com` 的 Cookie（即浏览器保持 QQ 邮箱登录态）。
2. 运行（不传任何参数；`requests` 已随工具安装在虚拟环境中，无需单独安装）：
   ```
   python -u download_invoice_pdfs.py
   ```

## 实现说明（基于抓包还原的接口）

| 步骤 | 接口 | 说明 |
|---|---|---|
| 获取 Cookie | `GET http://127.0.0.1:33445/api/cookies/query?url=https://wx.mail.qq.com/` | 获取 `cookie_header`；sid 取 Cookie 的 **`xm_sid`**（见下节），并以 `folderlist` 响应 `param.sid` 校准 |
| 搜索邮件 | `POST /list/search` | `page_now=0&page_size=50&keyword=发票&dirid=1`；从 0 开始翻页；响应 `body.list[]` 含 `unread`、`normal_attach`（含 download_url，不带 sid）、`total_num`；`highlight.eml_body` 证实搜索范围含正文 |
| 读邮件 | `POST /read/readmail` | `mailid=<id>&func=1`；获取权威附件列表与**带 sid 的 `download_url`**；**已确认 `func=1` 打开本身即置已读**（无需专门请求，分析见注意事项 3） |
| 下载附件 | `GET https://wx.mail.qq.com<download_url>` | 优先使用 readmail 返回的带 sid URL；302 跳转到 `/download/download?target=...` 后返回 PDF，requests 自动跟随 |

接口公共参数 `language=zh`、`r=<随机数字>`（防缓存）、`sid`（动态获取，非硬编码）。

## 会话 sid 来源（实际验证结论，重要）

- **`wx.mail.qq.com` 的会话 sid 必须取 Cookie 的 `xm_sid`**；Cookie 中同名的 `sid`（`.mail.qq.com` 域）是 QQ 域登录 sid（形如 `xxx&`），拿它请求 `xmlistlogicsvr` 等接口会返回 **`ret=-20002`（登录态失效）**；
- 脚本取值时优先 `xm_sid`，回退 `sid`，并去掉尾部 `&` 等拼接残留；随后以 `folderlist` 响应的 `param.sid` 校准；
- **接口报错排查**：服务端真正原因常在响应 `head.stack` 字段中（如 `ret=-20002` 时 `stack=登录态失效`，而 `msg` 往往为空）；脚本抛错时同时带上 `ret`、`msg`、`stack`，并对 `-20002` 附加“请确认浏览器已登录 wx.mail.qq.com 且插件已推送其 Cookie”的提示。

## 处理规则与顺序

- 邮件顺序：搜索结果按时间**降序**（最新优先），页内逐封、页间按 `page_now` 递增；
- 标题过滤：包含 `发票` 或 `报销`；
- 附件下载：单个 PDF 直接下载；多个 PDF 时文件名含 `发票/报销` 且不含 `行程` 的下载；
- 停止条件：某封邮件同时满足“标题含关键字 + 有 PDF 附件”且已读（`unread=0`）时，记录后停止，更早的邮件（含后续页）不再处理；
- 三类汇总：
  - 第一、三类邮件通过 `readmail` 获取权威数据（置已读）；
  - 第二类（标题不含关键字）不调用 `readmail`，仅依据搜索结果 `normal_attach` 记录，避免置已读副作用；
- 已读停止点邮件不调用 `readmail`（依据搜索结果的 `unread` 判断）。

## 抓包依据与注意事项

1. **搜索结果已含关键信息**：`/list/search` 响应的邮件条目自带 `unread`（已读状态）与 `normal_attach`（附件列表），脚本据此判断分类与停止条件；`readmail` 主要用于置已读与获取带 sid 的下载地址。
2. **人工下载“行程报销单”与规则的差异（请人工确认）**：本次抓包中人工实际下载了 `第三方网约车服务公司_如祺出行行程报销单.pdf`（文件名含“行程”），与“文件名包含行程则跳过”的规则冲突（前两次抓包人工下载的是“如祺出行电子发票.pdf”，符合规则）。脚本按提示词规则**跳过含“行程”的附件**；若实际也需要下载行程报销单，请调整脚本中 `ATTACH_SKIP_KEYWORD` 逻辑。
3. **已读状态机制分析（“未读变已读”由谁导致）**：通过对第三次抓包的逐请求比对得出结论——
   - **打开邮件的 `readmail` 请求本身就会置已读**：每次 `readmail func=1` 后紧跟的 `folderlist` 中收件箱 `unread_num` 立即递减 1（12→11→10→9→8→7，与逐封打开一一对应），期间无其他可修改状态的请求（`check_pic`/`info/report`/`getuserinfo` 均不改变已读状态）；重新搜索（约 1 分钟后）也确认这些邮件已变为已读；
   - 抓包中唯一出现的专门请求 `POST /mgr/mailmgr`（`mailid=...&func=4`，空响应）仅出现 1 次，与 `readmail func=6`（飞猪邮件，另一种打开/预览方式）在 1ms 内连发，同样达到已读效果——推测 `func=6` 为不自动置已读的预览式打开，由 `mailmgr func=4` 显式补标已读；两条路径殊途同归，**脚本使用 `func=1` 即可，无需调用 `mailmgr`**；
   - **前一晚已读邮件次日变回未读的原因（已由人工说明确认）**：人工为验证脚本行为，对部分邮件的未读/已读状态进行了**手动翻转**（如祺7月、票通、美团、云票等前一晚打开过的邮件被标回未读）。翻转操作发生在抓包记录之外，对应请求未被抓到（推测同样走 `/mgr/mailmgr`，但 func 参数值未知）；属人工验证行为而**非系统回滚**，不影响“遇到已读邮件即停止”机制的可靠性——正常使用中已读状态不会被系统自动改回。若需脚本复现“标为未读”，需补充抓包确认 `mailmgr` 对应的 func 参数。
4. **重新搜索不带 `dirid`**：人工最后重新搜索时请求不带 `dirid`（即全部文件夹范围）。脚本按用户要求固定为收件箱（`dirid=1`）；若需全文件夹搜索，删除 `search_page()` 中的 `dirid` 参数即可。
5. **停止机制的依赖**：脚本下载附件前会 `readmail` 置已读，与人工打开邮件行为一致；下次运行时，本次处理过的邮件将成为“已读停止点”，不会重复下载。如需让脚本重新处理某些邮件，可仿照人工验证做法，在网页上将其标为未读。
6. HTTPS 请求不做证书校验（`verify=False`），与内部约定一致。
