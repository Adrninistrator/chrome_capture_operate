# AI 分析前端页面与抓包内容的建议方法

供 AI Agent 执行时参考的失效模式警告与基线保存约定（过程性步骤按通用
Agent 能力自行组织，不在此罗列）。

## 必须避免的失效模式（真实失败案例提炼）

1. **会话相关参数不能硬编码**：ID/token/时间戳等是当时会话的实例值——
   在抓包记录中搜索该值，找到生成它的前序请求（如先查列表拿 ID），
   脚本运行时先调该请求再取值；找不到来源时提醒人工确认
2. **数据未必走接口**：可能 SSR 内嵌（如 `__NEXT_DATA__` 等 script
   标签）或纯前端过滤（筛选不产生新请求）；抓包记录中找不到页面数据
   时，用 chrome-devtools 分析页面确认数据来源
3. **先开抓包再操作**：否则漏掉最前面的关键请求（列表/登录），
   导致参数来源无法追踪
4. **元素定位用语义不用选择器**：chrome-devtools 操作页面时按角色/
   名称定位，不依赖 CSS 选择器——前端框架升级常改 DOM 结构
5. **分析网站后台接口格式以抓包请求数据为准**：接口的请求格式
   （参数结构、取值形态等）以抓包记录中实际发送的请求数据为准

## 基线保存约定（网站改版时快速对比）

- 生成脚本时把**数据来源契约**存为脚本子目录下 `baseline.md`
  （markdown 表格，人可读、AI 可解析、diff 友好）
- **页面结构本身不需要保存**：脚本只依赖数据来源契约，页面改版不
  影响未变的接口；改版失效时重抓新基线逐行对比即可
- 每行一个数据来源，列：功能用途 / 来源类型（接口 or SSR）/ URL
  路径与参数（SSR 写字段路径）/ 参数来源（固定值 / 来自哪个接口的
  哪个字段 / 人工输入）/ 使用的字段与路径 / 操作路径（到达该功能的
  菜单与页面入口）

| 功能用途 | 来源类型 | 路径 | 参数来源 | 使用字段 | 操作路径 |
|---|---|---|---|---|---|
| 查询工单列表 | 接口 | GET /api/orders?page={页码} | 页码为入参 | data.list[].id | 菜单"工单"→"查询" |
| 火车票列表 | SSR | __NEXT_DATA__.props.pageData.list | 出发/到达为入参 | [].trainNo | 首页→火车票查询 |

- **更新时机**：首次生成脚本时创建；网站改版脚本失效时重抓对比更新，
  按「URL 变化 / 参数增减 / 字段路径变化」定位需要修改的脚本位置

## 本项目约定

- 抓包分析：先读 index.md 汇总表，再按序号读明细文件；请求行与前端
  操作行在同一张表按时间排序——操作行的资源类型列为"操作"（序号/
  方法/大小等为占位值），URL 列为操作描述，时间精确到毫秒，用于
  对齐"做了什么操作"与"发了什么请求"
- 操作行由 DOM 事件监听注入自动捕获，格式为
  `页面操作[事件类型] 元素描述`，可附 `value=`（输入值）、`checked=`
  （勾选状态）、`key=`（按键）、`form=`（表单提交目标与方法）等
  字段；主要事件类型：click（点击）、change（填写值/勾选，回车
  提交时也会补记一条）、submit（表单提交）、keydown（F5/回车等
  按键）、route（SPA 路由变化）、page_load / pagehide（页面加载/
  卸载）
- 行尾"（合成）"表示该操作由程序（AI/脚本）触发而非人工；密码框
  的值记录为掩码 `***`；记录的事件类型可在"参数配置"标签页调整
  （默认不记按下/聚焦/滚动）
- 对齐方法：按时间邻近关系对应——点击/提交操作之后最先出现的
  XHR/Fetch 请求通常即该操作触发；change 行的 value 与请求 body/
  query 中的参数值一致时即可确认对应关系，请求参数的人工输入值
  优先从 change 行取（而不是从请求里反推）
- 文本输入只经 change（失焦/提交时）与回车补记两条路径捕获（不监听
  input，避免逐字符噪音）：AI 用 Runtime.evaluate 合成输入
  （赋值 + dispatchEvent('input')）不产生操作行——需要留痕时派发
  change 事件（`new Event('change', {bubbles: true})`）或触发回车，
  或用完整键盘模拟（chrome-devtools 的输入工具）
- 人工标记（mark）与操作注释（note）用途不同：mark 给会话目录改名加
  `_人工标记` 后缀（标记重要会话）；note 是抓包期间的时间点注释
- 脚本编写约束（运行环境、依赖、Cookie 获取等）看 api.md
  （项目根目录 api/api.md）
